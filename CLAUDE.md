# SirahDo — инструкции для Claude Code

Исламский планировщик: день строится вокруг 5 окон намаза. Expo (React Native) + TypeScript, данные только на устройстве.
Общение с пользователем — по-русски. Комментарии в коде — по-русски.

@AGENTS.md
@docs/PROJECT_STATE.md

## Правила работы (обязательны)

1. Перед ЛЮБЫМ изменением кода, функциональности, архитектуры, конфигурации или структуры проекта — сначала определить, какие документы относятся к задаче (карта ниже), и прочитать их.
2. Не полагаться только на память разговора. Если документация и код могут расходиться — проверить фактический код.
3. После изменения функциональности, требований, архитектуры, технологий или важных решений — проверить, какие документы это затронуло, и обновить их в той же задаче. Если смысл документа не изменился — не трогать его.
4. Не держать несколько противоречащих «актуальных» описаний одного функционала. Каждый факт живёт в одном документе, остальные ссылаются.
5. Документы описывают только АКТУАЛЬНОЕ состояние. Старые версии требований не хранить — история в Git. Заменённые важные решения — в `docs/DECISIONS.md` со статусом SUPERSEDED.
6. Перед compact или завершением крупного этапа — сверить и обновить `docs/PROJECT_STATE.md` (он должен оставаться коротким: удалять устаревшее, а не дописывать дневник).
7. Не возвращать из памяти решение, которое отменено более новым подтверждённым решением.

## Иерархия источников истины

1. Последняя явная инструкция пользователя в текущей задаче.

## Ключевые соглашения кода (подробно — ARCHITECTURE.md)

- Экраны работают с данными только через `useAppData()` (`src/lib/AppDataContext.tsx`). Новая сущность/операция: `storage.ts` → `AppDataContext.tsx` → экран.
- Цвета — только токены из `src/theme/colors.ts`. `Text`/`TextInput`/`Switch` — из `src/components/themed.tsx`, не из `react-native`. Иконки — `src/components/Icon.tsx` (Lucide). Без теней, радиус ≤ 8.
- Новые нативные зависимости — только если они есть в Expo Go; иначе предупредить пользователя (нужен dev build). Пакеты ставить `npx expo install`.
- Изменение формата хранимых данных — через миграцию (`SCHEMA_VERSION` в `storage.ts`).
- Перед тем как считать задачу готовой: `npx tsc --noEmit`, `npx expo lint`, `npx expo export -p web` (и `npx expo-doctor` при изменении зависимостей) — без ошибок.

## Особенности окружения (актуально на Mac пользователя)

- Кэш npm `~/.npm` частично принадлежит root → для npm/npx использовать `--cache ~/.npm-eas` или `npm_config_cache=$HOME/.npm-eas`. Флаг `-- --cache` у `npx expo install` ломает аргументы — только через переменную окружения.
- Проект лежит в `~/Projects/SirahDo` — вне iCloud. Не переносить на Рабочий стол/в Документы: там iCloud выгружает файлы (`dataless`), и Node/Expo зависают. Проверка: `find . -flags +dataless | wc -l`.
- Xcode нет (симулятора iOS нет) — визуальная проверка через веб-сборку во встроенном браузере; телефон пользователя — iPhone с Expo Go, связь только через `--tunnel`.
- Коммитить и пушить — только по просьбе пользователя.
