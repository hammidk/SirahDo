# SirahDo — единое ТЗ (MVP)

Объединяет: мастер-промпт, «ТЗ: Календарь, Todo-список, Трекер привычек» (22.09.2026) и «ТЗ: Исламское дополнение».
Если документы расходились, здесь записано итоговое решение, и оно главнее исходных. Решения, принятые при объединении, помечены **[решение]**.

---

## 0. Принципы (без исключений)

- День строится вокруг 5 окон между намазами. Намазы — несдвигаемые якоря.
- **Приложение рекомендует, а не решает.** Никакая автоматика или ИИ не меняет данные пользователя без его подтверждения.
- Свободное время показывается как возможность наполнить его благом.
- Привычки внедряются постепенно, без штрафов и «красных» индикаторов за пропуск.
- Вечером — анализ дня и дневник.

## 1. Навигация

**[решение]** Нижняя навигация из 4 пунктов:

| Таб | Содержимое |
|---|---|
| **Сегодня** | Окна намаза, задачи и события на сегодня, «Фокус дня», вечерний блок (Дневник) |
| **Календарь** | Режимы Расписание / День / Неделя / Месяц, события, задачи со сроком, намазы |
| **Трекер** | Привычки: неделя с кружками, список, статистика |
| **Обзор** | Входящие (вверху, со счётчиком), Избранное, Проекты (папки), История, Дневник |
| **Входящие** — НЕ отдельный таб | **[решение]** Входящие — первая строка в «Обзоре» со счётчиком, чтобы не перегружать таб-бар |

- **Профиль** (геолокация, город, метод расчёта, мазхаб) открывается иконкой-шестерёнкой в шапке «Сегодня».
- Плавающая кнопка **«+»** работает по контексту: Сегодня/Обзор/проект → задача (в проекте — сразу в этот проект, в Обзоре — во Входящие); Календарь → событие; Трекер → привычка.

## 2. Справочники (константы в коде)

- **Сферы жизни** (`SPHERES`): Вера, Здоровье, Ризк, Семья, Благотворительность, Цели/Идеи/Прочее. Используются в Task, Habit и Project (у проекта — опционально).
- **Теги по намерению** (`INTENTION_TAGS`): Ибада, Дунья, Обязательство. Это фиксированный чип. Он не заменяет пользовательские теги и не заменяет поле «Намерение».
- **Приоритет**: П1 (высший) / П2 / П3 / П4 (по умолчанию, «без приоритета»), как в Todoist. **[решение]** вместо low/medium/high; существующие данные мигрируются: high→1, medium→2, low→3.

## 3. Намаз

- Расчёт офлайн по координатам через `adhan`, с учётом метода и мазхаба из Профиля. **[решение]** Внешний API (Aladhan) не используется: локальный расчёт работает офлайн без ограничений.
- 5 окон: Фаджр→Зухр, Зухр→Аср, Аср→Магриб, Магриб→Иша, Иша→Фаджр (след. дня).
- UI: намазы — зафиксированные блоки-разделители в режимах День/Неделя/Расписание и на «Сегодня». Задача показывает подпись окна («Зухр → Аср»). На «Сегодня» — текущее окно и **сколько времени до его конца**.
- Город: геолокация через `expo-location`. Запасной вариант — ручной ввод города (`Location.geocodeAsync`).

## 4. Календарь

### 4.1 Экран
- Стиль Notion Calendar: плоский и спокойный.
- Сверху название месяца; по тапу разворачивается сетка месяца для быстрого перехода.
- Гамбургер открывает боковую панель:
  - режим: Расписание / День / Неделя / Месяц;
  - список календарей с чекбоксами (любая комбинация) и кнопкой «Создать календарь».
- В календаре показываются: события видимых календарей, задачи со сроком (отдельный системный слой «Задачи», тоже с чекбоксом), намазы.

### 4.2 Событие — форма
1. Название
2. Время: «Весь день»; начало (дата+время); конец (дата+время); повторение (§7)
3. Календарь + переопределение цвета события
4. Уведомления (§8)
5. Локация (текст)
6. Описание (текст)
7. Вложения: **[решение]** в MVP только ссылки; файлы и документы — следующий этап (нужен `expo-document-picker` и хранение файлов)

## 5. Todo (Обзор / Проекты)

### 5.1 Обзор
- **Входящие** — временный буфер нераспределённых задач (`projectId` пуст). **[решение]** Это не постоянная зона: задачу из Входящих можно одним действием перенести в проект, раздел или окно намаза. Сфера во Входящих необязательна.
- **Избранное**: проекты, фильтры, теги (звёздочка на каждом).
- **Проекты**: папки с вложенностью. В модели глубина не ограничена (`parentProjectId`). **[решение]** В UI — до 3 уровней.
- **Фильтры** (сохранённые): по сфере, тегу, тегу намерения, приоритету, сроку (сегодня / неделя / просрочено). **[решение]** Простой конструктор из чипов, без языка запросов.

### 5.2 Карточка проекта / раздела — «Намерение → Действие → Упование»
1. **Намерение** — свободный текст «зачем»; необязательно. В свёрнутом виде показывается первая строка, по тапу раскрывается.
2. **Действие** — задачи проекта, сгруппированные по разделам (разделы как в Todoist).
3. **Упование** — заглушка ИИ («Скоро: рекомендации ИИ»), без логики.

Намерение (проект/раздел) ≠ Ценность (задача). Не объединять.

### 5.3 Задача
**Компактный вид (строка списка):** чекбокс, название, короткое описание, срок, иконка напоминания, приоритет (цвет), теги, проект, сфера, подпись окна намаза. Иконка «⤢» открывает расширенный вид.

**Расширенный вид — все поля:**
- Название *(обязательно)*
- Описание с панелью форматирования. **[решение]** Лёгкий markdown (жирный, курсив, список, ссылка) через кнопки панели, без WebView-редактора.
- Чек-лист (подзадачи-галочки)
- Срок: быстрый выбор Сегодня/Завтра; календарь; время и длительность; повтор (§7)
- Напоминания (§8)
- Приоритет П1–П4
- Теги (пользовательские, несколько)
- Тег намерения (Ибада / Дунья / Обязательство)
- Проект / раздел (можно сменить прямо здесь; пусто — Входящие)
- Сфера жизни
- Окно намаза
- **Ценность** — ради чего выполняется
- Ожидаемый результат

**После завершения:** время начала, время окончания, короткий комментарий-анализ, причина переноса (если переносилась).
Для повторяющейся задачи при завершении создаётся следующее вхождение, а завершённое остаётся в Истории.

## 6. Трекер привычек

- Сверху — неделя с кружком выполнения на каждый день: заполнение = доля выполненных привычек за день. Непройденный день — пустой кружок, не красный.
- Ниже — список активных привычек. Кнопка выполнения увеличивает счётчик (например, «Зикр» — 3/5).
- **Создание:** название + иконка (эмодзи); описание; сфера; цель повторений в день (по умолч. 1); **дни недели** (по умолч. каждый день) **[решение: объединено из обоих ТЗ]**; напоминания (§8, несколько).
- **Серия (streak)** считается только по запланированным дням. Пропуск не «сжигает» прогресс: показываем «лучшая серия» и «всего выполнено», без штрафов.
- **Статистика:** неделя / месяц / год — процент выполнения, лучшая серия, календарь-теплокарта.

## 7. Повторение (общий компонент для события и задачи)
- Быстрые пресеты: не повторять / ежедневно / по будням / еженедельно (в этот день) / ежемесячно / ежегодно.
- Гибко: интервал (каждые N дней/недель/месяцев/лет), дни недели, окончание (никогда / дата / N раз).

## 8. Напоминания (общий компонент: событие, задача, привычка)
- Быстрый выбор: в момент срока, за 5 / 10 / 30 мин, за 1 час, за 1 день.
- Гибко: несколько напоминаний, произвольное смещение или конкретные дата+время.
- Реализация: локальные уведомления `expo-notifications`. При изменении, завершении или удалении сущности её старые уведомления отменяются.

## 9. Сегодня
- Шапка: дата (+ хиджра), текущее окно и таймер до конца окна, шестерёнка → Профиль.
- Лента 5 окон; в каждом окне его задачи и события.
- **Фокус дня** — детерминированные подсказки по календарю (пятница → Джума и сура аль-Кахф; понедельник/четверг → сунна-пост; последняя треть ночи и т.п.) + баннер-заглушка ИИ. Никакой генерации.
- Привычки на сегодня (компактно, с быстрой отметкой).
- Вечерний блок (после Магриба или по кнопке): «Анализ дня» → Дневник.

## 10. Дневник и История
- **Дневник** (`DiaryEntry`): запись на дату — свободный текст + «что получилось», «что изменить завтра», отметка благодарности. Открывается из вечернего блока «Сегодня» и из «Обзора».
- **История**: журнал прошедших дней — выполненные / перенесённые / невыполненные задачи, выполненные привычки, запись дневника. Открывается из «Обзора»; в Календаре тап по прошедшему дню открывает его историю.

## 11. ИИ — только заглушки
Места: баннер на «Сегодня», блок «Упование», «Фокус дня», подсказка при пропуске намаза («Скоро: предложим пересобрать день»).
Бэклог (не делаем): пересборка дня с подтверждением, уточнение намерения при создании задачи (всегда пропускаемое), рекомендации дуа/азкаров/доп. намазов.

## 12. Модель данных

```ts
Calendar   { id, name, color, visible, order }
Event      { id, title, allDay, start, end, recurrence?, calendarId, colorOverride?,
             reminders: Reminder[], location?, description?, links: string[], createdAt }
Project    { id, title, parentProjectId?, sphere?, intentionTag?, intention?, favorite?, order, archived? }
Section    { id, projectId, title, intention?, order }
Tag        { id, name, color?, favorite? }
Filter     { id, name, criteria: { spheres?, tagIds?, intentionTags?, priorities?, due? }, favorite?, order }
Task       { id, title, description?, checklist: {id,text,done}[],
             due?: { date: 'YYYY-MM-DD', time?: 'HH:mm' }, durationMinutes?, recurrence?,
             reminders: Reminder[], priority: 1|2|3|4, tagIds: string[], intentionTag?,
             projectId?, sectionId?, sphere?, namazWindow?, value?, expectedResult?,
             status: 'active'|'done', createdAt, startedAt?, endedAt?, comment?, postponeReason? }
Habit      { id, name, icon, description?, sphere?, targetCountPerDay, weekdays: number[],
             reminders: { time: 'HH:mm' }[], archived?, order, createdAt }
HabitLog   { id: `${habitId}_${date}`, habitId, date, completedCount }
DiaryEntry { id: date, date, text, wentWell?, changeTomorrow?, gratitude?, createdAt, updatedAt }
Recurrence { freq: 'day'|'week'|'month'|'year', interval, weekdays?: 1..7, until?, count? }
Reminder   { kind: 'offset', minutes } | { kind: 'at', at: ISO }
Settings   { latitude?, longitude?, locationLabel?, calculationMethod, madhab }
```

Примечания к модели:
- id уведомлений не хранятся в данных: идентификатор уведомления строится из сущности (`task:<id>:<n>`), поэтому напоминания снимаются по префиксу.
- Повторяющаяся задача при выполнении остаётся в Истории как выполненная, а следующее вхождение создаётся новой задачей.
- Задача без времени: напоминания считаются от 09:00 дня срока.

## 13. Технологии
- Стек из мастер-промпта (Expo SDK 57, expo-router, TypeScript strict, `adhan`, `dayjs`, `expo-notifications`, `expo-location`).
- **Хранение: AsyncStorage** через `storage.ts` → `AppDataContext` → экраны. **[решение]** Не «в памяти», как в ТЗ от 22.09: persistence уже сделано. Firebase — позже; меняется только `storage.ts`.
- **[решение]** Все сетки (месяц/неделя/день), пикеры и редакторы — свои компоненты, без новых нативных зависимостей, чтобы приложение продолжало работать в Expo Go. `react-native-calendars` и `@react-native-community/datetimepicker` не подключаем.

## 14. Вне MVP
Реальный ИИ, облачная синхронизация, серверные push-уведомления, вложения-файлы, совместные проекты.

## 16. Запуск и сборка
- Разработка: `npx expo start` (Expo Go на телефоне; после смены зависимостей — `npx expo start --clear`).
- Проверки: `npx tsc --noEmit`, `npx expo lint`, `npx expo-doctor`, `npx expo export -p web`.
- Сборка (нужен аккаунт Expo): `npx eas-cli@latest login`, затем `npx eas-cli@latest build -p android --profile preview` (APK для теста) или `--profile production` для сторов.
- Идентификатор приложения `com.sirahdo.app` можно поменять в `app.json` до первой загрузки в стор — после этого он постоянный.
- Вне MVP: реальный ИИ, облачная синхронизация (Firebase — `src/lib/firebase.ts`), серверные push, вложения-файлы.
